# 一、玩具示例

> **数据来源**: MUTAG 数据集（Debnath et al., J. Med. Chem. 1991；4,247 个真实化合物）

## 选定的真实分子

### 分子 1：致突变


| 属性       | 值                         |
| ---------- | -------------------------- |
| 标签       | 1（致突变）                |
| 重原子数   | 12                         |
| 键数       | 16                         |
| 关键子结构 | NO₂（硝基）连接在呋喃环上 |

NO₂（硝基）是已知的毒性基团——Ames 测试阳性。

### 分子 2：不致突变


| 属性     | 值            |
| -------- | ------------- |
| 标签     | 0（不致突变） |
| 重原子数 | 14            |
| 键数     | 16            |
| 关键特征 | 无 NO₂ 基团  |

## 问题设定

```
G_0 = (V={全部原子ID}, E=∅, X=∅)     # 仅知节点索引
B = 5                                   # 揭示预算（5步）
成本模型：1 节点揭示 = 1 单位

对 b = 1 ... B：
  a_b = 策略(G_{<b})                    # 选择揭示哪个节点
  G_b = 揭示(G_{b-1}, a_b)              # 揭示节点 + 关联边同时可见

ŷ = 分类器(G_B)                         # 从部分观测预测
```

## 三种揭示策略对比

### 策略 A：随机揭示

随机选择节点，不利用图结构。B=5 时大概率错过 NO₂ 基团，把预算浪费在普通碳原子上。

**预期结果**：常将致突变分子误判为不致突变。

### 策略 B：BFS 揭示

从随机种子沿化学键 BFS 扩散。有机分子呈链状，BFS 自然沿分子骨架追踪到官能团。

**预期结果**：更可能在预算内发现 NO₂ → 正确分类。

### 策略 C：度中心性揭示

优先揭示度数最高（连接邻居最多）的节点。高度数节点常在环结构或官能团中，是分子骨架的核心枢纽。

**预期结果**：优先捕获"枢纽"节点，有效获取分子骨架信息。在分子图中，环上的碳原子度数最高（连接 2-3 个邻居），比末端的碳更早被揭示。

## 核心

1. **预算很重要**：预算太小，BFS 也会失败。有趣的是中间区域，以及能否动态估计预算步数。
2. **简单启发式优于随机**：BFS 沿分子骨架、中心性优先枢纽——图拓扑本身提供有用的结构先验。
3. **最优策略依赖领域**：
   - 分子图 → BFS 有效（原子链状/环状连接）
   - 社交网络 → 度中心性有效（重要节点广泛连接）
   - → 学习型策略可以发现不同领域最优策略
4. **NO₂ 是判别性证据**：12 个原子中只有少数携带致突变信号。模型必须在预算内"挣得"这份证据。

# 二、关键设定

## 2.1 G_0的成分

G_0 是模型在揭示过程开始前就能看到的初始信息。不同选择决定了模型的"起点难度"。

### 方向 A：最简模式——仅节点 ID

```
G_0 = (V, ∅, ∅)
```


| 可见                      | 不可见        |
| ------------------------- | ------------- |
| 节点索引 {0, 1, ..., n-1} | 节点特征 X    |
| 图规模                    | V             |
| —                        | 节点标签/类型 |
| —                        | 全局图属性    |

**优点**：最纯粹的问题设定，最接近"从零开始阅读"的隐喻。模型没有任何先验可依赖。
**缺点**：初始选择完全是盲目的（随机或对抗性开局）。
**推荐**：⭐ 作为 M3 首个基准的默认设定。

### 方向 B：ID + 全局统计量

```
G_0 = (V, stats)
其中 stats = { |V|, |E|, avg_degree, diameter, ... }
```


| 可见                   | 不可见     |
| ---------------------- | ---------- |
| 节点索引               | 节点特征 X |
| 图规模                 | V          |
| 平均度数、直径等全局量 | 节点级结构 |

**优点**：模型知道图"有多大、多密"，可以做预算分配。
**缺点**：仍不知道"证据在哪里"。
**适合场景**：社交网络、引文网络等全局统计有意义的领域。

### 方向 C：节点特征可见，边隐藏

```
G_0 = (V, X, ∅)
```


| 可见                    | 不可见             |
| ----------------------- | ------------------ |
| 节点索引 + 全部节点特征 | 边集合（拓扑结构） |
| 每个节点的属性          | 节点之间的连接关系 |

**优点**：模型可以根据特征做初始选择（如"优先看带硝基的原子"），更贴近特征获取场景。
**缺点**：图结构的"惊奇"减少了——只剩边需要揭示。
**适合场景**：分子图（已知原子类型，未知键连接）、知识图谱。

### 方向 D：k 个种子节点完全揭示

```
G_0 = (V, X_seed, E_seed)
其中随机选择 k 个节点，揭示其特征 + 所有关联边
```


| 可见                    | 不可见          |
| ----------------------- | --------------- |
| k 个种子节点的特征 + 边 | 其余 n-k 个节点 |
| 种子节点的邻域          | 全局图结构      |

**优点**：有初始线索可循，更接近真实"从某个入口开始阅读"的场景。
**缺点**：k 的选择引入额外超参数。
**适合场景**：安全溯源图（已知受害节点，追踪攻击链）。

### 方向 E：全局拓扑已知，特征隐藏

```
G_0 = (V, E, ∅)
```


| 可见                 | 不可见       |
| -------------------- | ------------ |
| 完整的拓扑结构（边） | 所有节点特征 |
| 图的骨架             | 节点属性     |

**优点**：模型可以在已知骨架的情况下规划"测量"路线，更接近 Policy-Learn 的设定。
**缺点**：失去了"探索未知拓扑"的挑战。
**适合场景**：传感器网络（已知部署拓扑，需选择性读取传感器数据）。

### 方向 F：部分拓扑 + 部分特征混合

```
G_0 = (V, E_partial, X_partial)
初始随机揭示一部分边（如 10%）和一部分节点特征
```


| 可见               | 不可见       |
| ------------------ | ------------ |
| 随机子集的边       | 其余边       |
| 随机子集的节点特征 | 其余节点特征 |

**优点**：最灵活——可调节初始信息比例作为难度杠杆。
**缺点**：超参数多，基准设计复杂。
**适合场景**：消融实验，研究不同初始信息量下的策略行为。

### 对比总结


| 方向           | 初始信息量 | 策略难度 | 推荐优先级 | 适合场景   |
| -------------- | ---------- | -------- | ---------- | ---------- |
| A：仅 ID       | 最少       | 最难     | ⭐ M3 默认 | 纯图阅读   |
| B：ID + 统计量 | 少         | 难       | P1         | 大规模图   |
| C：特征可见    | 中         | 中       | P1         | 分子图     |
| D：k 种子      | 中（可控） | 中       | P2         | 安全溯源   |
| E：拓扑已知    | 多         | 易       | 参考       | 传感器网络 |
| F：混合        | 可控       | 可控     | 消融用     | 实验研究   |

## 2.2 阅读动作的定义

方向 1：节点揭示（Node Reveal）

```
reveal_node(v) → 揭示节点 v 的全部特征 + 可选：v 的关联边
```


| 变体                       | 揭示内容                               | 单位成本 |
| -------------------------- | -------------------------------------- | -------- |
| reveal_node(v)             | v 的特征                               | 1        |
| reveal_node(v) + edges     | v 的特征 + 所有关联边                  | 1        |
| reveal_node(v) + neighbors | v 的特征 + 邻居节点 ID（不含邻居特征） | 1        |

**分析**：最自然的原子动作。在分子图中对应"测量这个原子的属性"。

### 方向 2：边揭示（Edge Reveal）

```
reveal_edge(u, v) → 揭示边 (u, v) 是否存在 + 可选：边属性
```


| 变体                | 揭示内容                      | 单位成本 |
| ------------------- | ----------------------------- | -------- |
| reveal_edge(u,v)    | 边 (u,v) 的存在性             | 1        |
| reveal_edge(u,v)    | 存在性 + 边特征（权重、类型） | 1        |
| reveal_all_edges(v) | v 的所有关联边                | deg(v)   |

**分析**：适用于拓扑比特征更重要的场景（如社交网络的关系发现）。

### 方向 3：邻域揭示（Neighborhood Reveal）

```
reveal_neighborhood(v) → 揭示 v 的所有邻居节点（含特征）+ 所有关联边
```


| 变体                   | 揭示内容             | 单位成本     |
| ---------------------- | -------------------- | ------------ |
| reveal_neighborhood(v) | v 的 1-hop 邻居 + 边 | 1 +          |
| reveal_khop(v, k)      | v 的 k-hop 自我网络  | Σ_{i=0}^{k} |
| reveal_ego_net(v, k)   | k-hop 子图完整揭示   | O(           |

**分析**：信息量大，效率高，但成本非线性。适合分子图——一次揭示一个官能团。

### 方向 4：特征维度揭示（Feature Dimension Reveal）

```
reveal_feature(v, dim) → 揭示节点 v 的第 dim 维特征
```


| 变体                  | 揭示内容                    | 单位成本 |
| --------------------- | --------------------------- | -------- |
| reveal_feature(v, d)  | 单维特征                    | 1/d_feat |
| reveal_feature_dim(d) | 全局第 d 维特征（所有节点） | n/d_feat |

**分析**：最细粒度。类似"逐步测量每个原子的质量、电荷、键类型"。

### 方向 5：证据单元揭示（Evidence Unit Reveal）

```
reveal_evidence_unit(e) → 揭示一个预定义的"证据单元"
```

证据单元是预定义的子结构，如：

- 官能团（分子图）：NO₂、COOH、苯环
- 社区（社交网络）：稠密连接的子图
- 路径（溯源图）：攻击链

**优点**：语义级别的高效动作。
**缺点**：需要先验知识来定义证据单元——可能在 M4/M5 阶段由学习型策略自动发现。

### 方向 6：随机游走揭示（Random Walk Reveal）

```
reveal_random_walk(v, L) → 从 v 出发走 L 步随机游走，揭示沿途所有节点+边
```


| 变体                         | 揭示内容                 | 单位成本 |
| ---------------------------- | ------------------------ | -------- |
| reveal_random_walk(v, L)     | 沿途 L 个节点 + L-1 条边 | L        |
| reveal_guided_walk(v, L, π) | 策略 π 引导的有偏游走   | L        |

### 方向 7：查询式揭示（Query-based Reveal）

```
reveal_query(Q) → 揭示满足查询 Q 的所有节点/边
```

例如：

- reveal_query("出度 > 10 的节点") — 揭示所有高度数节点
- reveal_query("原子类型 = N 的节点") — 揭示所有氮原子
- reveal_query("重量 > 12 的边") — 揭示所有权重大的边

**优点**：声明式、高效。
**缺点**：要求模型理解查询语义。

### 动作类型对比


| 动作类型        | 粒度 | 信息密度 | 实现复杂度 | M3 推荐 |
| --------------- | ---- | -------- | ---------- | ------- |
| 1：节点揭示     | 中   | 中       | 低         | ⭐ 默认 |
| 2：边揭示       | 细   | 低       | 低         | P1      |
| 3：邻域揭示     | 粗   | 高       | 低         | ⭐ 推荐 |
| 4：特征维度揭示 | 最细 | 最低     | 中         | P2      |
| 5：证据单元揭示 | 语义 | 高       | 高         | M4/M5   |
| 6：随机游走揭示 | 中   | 中       | 中         | P2      |
| 7：查询式揭示   | 可变 | 高       | 高         | P2      |

**M3 建议**：起点用"节点揭示"（每步揭示 1 个节点特征 + 关联边），同时保留邻域揭示作为扩展。

## 2.3 预算的基本单位


预算 B 和成本模型决定了"阅读"的资源和约束。

### 2.3.1 预算 B 的含义


| 解释          | 含义                                | 示例                           |
| ------------- | ----------------------------------- | ------------------------------ |
| 揭示步数      | B = 最多做多少次揭示动作            | B = 5 → 最多选 5 个节点       |
| 揭示节点数    | B = 最多揭示多少个节点（不计边）    | 揭示邻域时，只有根节点消耗预算 |
| 信息预算      | B = 揭示的信息总量（如节点数+边数） | B = 20 → 节点+边总数 ≤ 20    |
| 时间/计算预算 | B = 允许的计算时间/FLOPs            | B = 100ms → 实时推理场景      |

### 2.3.2 成本模型

#### 模型 1：统一成本（Uniform Cost）

```
cost(action) = 1   （所有揭示动作单位成本相同）
```

**优点**：最简单，易于基准比较。
**缺点**：不符合直觉——揭示度数为 100 的节点和度数为 1 的节点成本相同。
**推荐**：⭐ M3 默认。

#### 模型 2：度数加权成本（Degree-Weighted Cost）

```
cost(reveal_node(v)) = 1 + α · deg(v)
cost(reveal_edge(u,v)) = 1
cost(reveal_neighborhood(v)) = 1 + deg(v)
```

**直觉**：连接越多的节点，"测量"越费时。
**应用**：社交网络中，揭示一个 KOL 的成本高于普通用户。

#### 模型 3：特征维度加权成本

```
cost(reveal_node(v)) = d_feat(v) / d_avg
```

节点特征维度不同时（如原子类型 vs 键角），成本可不同。

#### 模型 4：层级成本（Hierarchical Cost）

```
不同类型动作有不同基础成本：
  base_cost(reveal_node) = 1
  base_cost(reveal_edge) = 0.5
  base_cost(reveal_neighborhood) = 3
  base_cost(reveal_khop) = 5
```

**优点**：模型可以权衡"便宜但信息少"vs"贵但信息多"的动作。
**缺点**：超参数增多。

#### 模型 5：探索折扣（Exploration Discount）

```
cost(reveal_node(v)) = 1 / (1 + β · times_visited(v))
```

访问过的区域越多次，再次探索成本越低（类似"已经熟悉这里了"）。

#### 模型 6：自适应成本（Adaptive Cost）

```
cost(action) = f(state, action)
```

成本函数由环境决定，可能是非平稳的。例如：某些节点在特定条件下才能揭示。

### 2.3.3 B 值的选择


| B 值     | 场景 | 预期效果     |
| -------- | ---- | ------------ |
| B ≪     | V    | （如 B=1~3） |
| B ≈ log | V    |              |
| B ≈ 0.3 | V    |              |
| B =      | V    |              |

**M3 建议**：设置 B = {1, 2, 3, 5, 10, 20} 多个值，绘制预算-性能曲线，找到"有趣区间"。

## 2.4 通俗口语、以及数学符号

### 4.1 基础变体：图分类

**自然语言**：

我们有一个图 G，它有一个标签 y（例如"这个分子有毒吗？"）。但我们不能看到 G 的全部内容——开始时我们只能看到节点编号，就像一本合上的书的目录。我们有一个预算 B，可以"翻开"B 次。每次翻开时，我们选择一个节点，看到它的属性以及它和哪些节点相连。B 次翻开后，我们必须基于看到的部分信息做出分类判断。目标是：在同样的预算下，看得比随机更好。

**数学定义**：

```
给定图 G = (V, E, X)，标签 y ∈ {0, 1, ..., C-1}
初始观测 G_0 = (V, ∅, ∅)
预算 B ∈ ℕ⁺

对 b = 1, 2, ..., B：
  a_b = π(G_{<b})                          ← 策略根据历史选择动作
  G_b = ψ(G_{b-1}, a_b)                    ← 揭示动作更新观测
  G_{<b} = {G_0, a_1, G_1, ..., a_{b-1}, G_{b-1}}  ← 历史

最终预测：
  ŷ = φ(G_B)                               ← 分类器基于部分观测预测

目标：
  max_{π, φ} E_{(G,y)∼D}[𝟙(ŷ = y)]
  s.t. cost(π) ≤ B
```

### 4.2 变体：节点分类

**自然语言**：

不同于对整个图分类，我们关心的是图中某个特定节点的标签（如"这个用户是欺诈者吗？"）。策略需要选择揭示哪些节点和边来辅助目标节点的分类。

**数学定义**：

```
给定图 G = (V, E, X)，目标节点 v_target，标签 y_target
G_0 中 v_target 的特征已知（或部分已知），其余隐藏
预算 B 用于揭示其他节点来辅助判断

ŷ_target = φ(G_B, v_target)
```

### 4.3 变体：边预测

**自然语言**：

预测两个节点之间是否存在一条边。这在"图中只有部分边可见，需要推断隐藏边"的场景中很自然。

**数学定义**：

```
给定 G_partial，目标边 e = (u, v) 未知
通过选择性揭示节点/边来推断 e 是否存在

ŷ_edge = φ(G_B, u, v)   ∈ {0, 1}
```

### 4.4 变体：回归任务

**自然语言**：

标签 y 是连续值（如分子的溶解度、药物的结合亲和力）。其他设定与图分类一致。

**数学定义**：

```
y ∈ ℝ
损失函数：ℓ(ŷ, y) = (ŷ - y)² 或 MAE
目标：min E[ℓ(ŷ, y)]
```

### 4.5 变体：多标签分类

**自然语言**：

一个图同时有多个标签（如分子同时有"毒性"和"溶解度"属性）。预算约束下需要高效揭示对不同标签都有用的证据。

**数学定义**：

```
y ∈ {0, 1}^K  （K 个二分类标签）
ŷ = φ(G_B) ∈ [0, 1]^K
目标：最大化 K 个标签的宏/微平均指标
```

### 4.6 变体：开集/分布外检测

**自然语言**：

训练时见过的图类别是固定的，但测试时可能出现未知类别的图。预算阅读策略需要不仅能分类已知类别，还能识别"我没见过这种图"。

### 4.7 统一数学框架

```
┌──────────────────────────────────────────────────┐
│          预算约束图阅读 — 统一框架                  │
│                                                    │
│  输入空间:  G = (V, E, X),  |V| = n               │
│  标签空间:  Y  (分类/回归/多标签/结构化)            │
│  初始状态:  G_0 ∈ Obs(G)  (部分观测)              │
│  动作空间:  A  (揭示节点/边/邻域/特征维度/证据单元)  │
│  预算约束:  B ∈ ℕ⁺                                 │
│  成本函数:  c: A → ℝ⁺                              │
│  转移函数:  ψ: Obs × A → Obs                       │
│  策略 π  :  (Obs)^* → A                           │
│  分类器 φ:  Obs → Y                                │
│                                                    │
│  优化目标:                                         │
│    max_{π,φ} E[ 指标(φ(G_B), y) ]                  │
│    s.t.  Σ_{b=1}^{B} c(a_b) ≤ B                   │
│                                                    │
│  特殊情形:                                         │
│    - B = n, Obs₀ = full → 标准图分类                │
│    - A = {reveal_node}, c(·) = 1 → 节点揭示版本     │
│    - B → ∞ → 自适应特征获取（无预算约束）            │
└──────────────────────────────────────────────────┘
```
